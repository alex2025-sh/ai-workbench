# 前端交互设计（简化版）

React 18 + Vite + TypeScript + Ant Design 5，运行方式见 `web/README.md`。接口见 `app/rpc/workbench.proto`，契约见 [task-type-spec.md](task-type-spec.md)。

## 路由

| 路由 | 页面 |
| --- | --- |
| `/tasks` | 任务工作台：我的任务 / 待认领 / 我经手的 |
| `/tasks/:id` | 任务详情，Lark 卡片「在工作台处理」的深链（认领节点的群消息也跳到这里认领） |
| `/config/task-types` | 任务类型列表 |
| `/config/task-types/:key` | 任务类型详情（已发布版本只读：定义、版本、JSON） |
| `/config/task-types/:key/edit` | 任务类型编辑（四步表单） |

## 任务工作台 `/tasks`

三个 Tab，都按优先级分区展示卡片网格（每区 9 张、各自「查看更多」，分区标题的计数来自第一页的 `counts`）：

| Tab | 内容 | 筛选 |
| --- | --- | --- |
| 我的任务 | 我名下的任务 | 状态（默认未完结）、优先级 |
| 待认领 | 认领节点上还没人认领的任务，所有人可见（群消息被刷掉时也能在这里找到） | 优先级 |
| 我经手的 | 我处理过、现在不在我名下的任务（升级、转交后），只读 | 优先级 |

卡片：优先级、状态、标题；任务类型 · 当前节点 · 推迟信息 · 处理人；卡片的前 3 个字段；操作按钮。按钮来自服务端（`can_claim` / `can_start` / `can_transfer` / `actions`，已按调用人过滤），卡片上最多直接显示 2 个，其余收进「更多」：

- 认领（先到先得，被别人抢先时提示并刷新）/ 开始处理；
- 转交：弹窗填新处理人与原因（必填）；认领节点（`claim_node`）可以切换为「放回待认领」；
- 已处理、无需处理：二次确认；推迟：选择时长；升级：弹窗显示升级到哪个节点并可填备注；
- 业务链接：新窗口打开，不改变状态。

操作同步生效，完成后重新加载所在分区；任务已被别人处理（`Aborted` / `FailedPrecondition`）时提示并刷新。

## 任务详情 `/tasks/:id`

- 左侧：卡片（与 Lark 一致）、全部业务字段（KV 表格，已脱敏）、流程图（节点链，当前节点蓝色、走过的绿色）。
- 右侧：状态、优先级、当前节点、处理人（待认领时显示「待认领」）、推迟至、结果、数据源 key、转交次数；操作按钮（同卡片，平铺，含转交）；调整优先级；处理历史时间线（创建时交给谁、怎么分到的，认领、转交 from → to 与原因、再次提醒）。
- 经手人只读：顶部提示「任务现在由 X 处理，你可以查看整个流程，但不能处理」。待认领的任务所有人可见；其他没有参与的人返回 403。

## 任务类型编辑 `/config/task-types/:key/edit`

四步表单，全程不需要写 JSON 或表达式（右上角可以查看只读 JSON）：

1. **数据源**：基本信息（名称、命名空间、优先级、描述）；类型（定时 SQL / API 推送 / Kafka）。SQL：选数据源连接、填 cron（旁边显示中文，如「每分钟」）、写查询，「试跑」在只读事务中执行并显示 key 与各列的前 20 行，「用结果生成字段」把新列加入字段。API / Kafka：显示消息格式。
2. **字段**：表格编辑字段名、显示名、类型、脱敏、枚举取值，上移下移删除；「用于」列标出被卡片、分配、链接引用。
3. **节点**：画布显示 start → 节点 → end，连线由动作生成（升级连下一个节点，已处理 / 无需处理连 end），不能手画；右上角添加节点。点节点在下方编辑：名称、处理人（按业务关系：关系 + 字段 + 兜底人；一批人中随机：候选人，输入邮箱回车；群里认领：Lark 群 chat_id + 无人认领时多久再提醒）、动作（最后一个节点不能升级；转交默认勾选）、链接按钮与地址、推迟时长、Lark 通知；前移、后移、删除。节点 id 自动生成（`n_` + 6 位随机字符），不展示也不需要填写。
4. **卡片**：标题（「插入字段」）与卡片字段（多选，按选择顺序）；右侧用试跑结果的第一行（没有时用样例数据）实时预览，可切换预览的节点，预览由后端渲染。

草稿：修改后 800ms 自动保存，同一时刻只有一个保存请求；返回的问题标在步骤条（「n 个问题」）与对应表单项上。revision 冲突时保留本地修改，可查看自己的 JSON 或以服务端为准重新加载。「校验」做完整校验（含数据源连接、业务关系是否存在）；「发布」需要 `task_type.publish`，有问题时不发布并跳到第一个问题所在的步骤；「丢弃草稿」回到已发布版本（从未发布的类型会被删除）。

## 任务类型详情 `/config/task-types/:key`

与编辑页相同的四部分只读展示，数据源下方显示运行状态（上次 / 下次执行、上次行数、新建、关闭、错误）；另有「版本」与「JSON」Tab。
